**Celetis entry.** Before any step or response, including commentary or an announcement, bind `<plugin>` to the absolute prefix before `/skills/<name>/SKILL.md` in the path of this loaded file. Then read `<plugin>/references/procedures/entry.md` whole, in one read, and follow it before any product-path scan. Do this on each invocation, including a same-session handoff.

# Create verification recipes

1. **Choose the scope and home.**
   - Read the project's instructions, existing verification documentation, relevant source,
     and available execution tools.
   - Read `<plugin>/references/procedures/verification-recipes.md` and apply "Recipe content"
     and "Explicit operations".
   - Resolve one document home before editing.
   - Select up to three core user flows from the documented product purpose and supported
     public entry points, or use the user's explicit creation scope.
   - State the selected flows before execution.
   - A diagnostic alone does not count as a core flow.
2. **Write usable instructions.**
   - Add or update each selected recipe and its map link in that home, with the fields of
     "Recipe content".
   - Reuse shared setup by reference.
   - Every selected entry needs concrete supported actions and an expected outcome.
   - A placeholder is not coverage.
   - Preserve unrelated recipes and execution references.
   - The default scope limit bounds selection, not the size of an existing map.
3. **Exercise the recipes.**
   - Read `<plugin>/references/procedures/runtime-verification.md` and apply
     "Confirming a target", "Evidence lifetime", and "Reports and deferred checks".
   - Record the absolute report destination before execution.
   - Execute the retained instructions for at least one selected real user flow end to end.
   - Compare each final executable recipe with its execution record under "Recipe content".
   - Renew affected evidence after an instruction or target change.
   - Continue independent flows when a prerequisite, permission, tool, or target gap blocks
     another.
   - Report product defects without changing product code or weakening the expected result.
4. **Report the result.**
   - Account for cleanup under "Explicit operations".
   - Confirm that the report and failure evidence remain readable.
   - Creation is complete only with at least one selected core flow's valid PASS and
     accounted cleanup.
   - Report each other selected flow's outcome or unexecuted status separately; this is not
     proof of the whole map.
   - With no valid PASS, retain useful recipes as drafts and report the exact gap and next
     action.
   - Save the report by the runtime procedure and link it in the final reply, with the
     changed document and pointer paths.
