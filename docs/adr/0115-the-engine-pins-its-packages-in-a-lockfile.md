## Context

The daemon protocol was checked by hand: private helpers tested each field, and each parser wrote its type a
second time as a TypeScript type. The maintainer chose "fewer parser bugs and established way" (parent decision 1):
one Zod schema gives the runtime check and the type. Zod needed a home, and the only third-party code of the engine
was a vendored `yaml` bundle with a hash check, because ADR-0025 said that plugin users install no package
dependency. The maintainer chose a package manager with exact pins and a lockfile in place of a copy (parent
decisions 3 and 4), and the scope of the manifest is the engine, because only the engine uses packages.

## Constraints and evidence

- The launcher flags stay (`--no-env-file --no-install --config=/dev/null --no-macros`). A package in the
  `node_modules` of an ancestor folder resolves under them (the probe of the spec of #348), so one manifest in
  `engine/` serves each engine file.
- `bun install --frozen-lockfile` with no `bun.lock` installs from `package.json` and writes no lockfile, so the
  install step checks that `engine/bun.lock` exists itself (the probe of the spec of #348). With a `package.json`
  that disagrees with `bun.lock`, the frozen install and its `--dry-run` resolve and download first, then exit 1 with
  `lockfile had changes, but lockfile is frozen` (the plan probe). So the gate does not run them: it installs
  nothing and needs no network.
- `bun.lock` is JSON with trailing commas. `Bun.JSONC.parse` parses it, `{"a":[1,],}` gives `{"a":[1]}` (the plan
  probe). The gate reads `engine/bun.lock` with it.
- A static import of a missing package fails before any statement of the importing file runs. So the gate checks
  `engine/package.json`, `engine/bun.lock`, and `engine/node_modules` in a preflight of `execute`, and three imports
  of `scripts/verify.ts` are dynamic.
- Zod 4.6.7 counts the length of a string in code points, and today's `textLimit` of 4096 counts UTF-16 units:
  `z.string().max(1)` accepts `"\u{1F600}"` (the plan probe). Each bounded text uses a refinement on `value.length`.
- `z.record` drops a `__proto__` key with no error, and a parse returns a new object in schema key order (the plan
  probe). Each object is a `z.strictObject` in the key order of today's type.
- The browser page imports only types of the queue. So the queue schemas and their types are in
  `engine/lib/queue/types.ts`, which the browser program of the gate already checks, and the shared forms are in
  `engine/lib/state/schemas.ts`. `engine/lib/state/fields.ts`, `engine/lib/config/core.ts`, `engine/hooks/`, and
  `engine/board/page/` import no Zod.
- The probes ran on macOS with Bun 1.4.4. Windows, Linux, a cold package cache, and the start cost of a full command
  are not checked. An import of Zod 4.6.7 added about 11 to 13 ms to a process in the probe of the spec.

## Decision

1. **Exact pins in a lockfile.** `engine/package.json` has `"private": true` and two dependencies, `zod` `4.6.7` and
   `yaml` `2.9.1`, as exact versions. `engine/bun.lock` is the text lockfile of Bun 1.4.4. The repository root,
   `scripts/`, and `plugins/` have no package file. The gate tools of `scripts/install-tools.ts` stay as they are.
2. **One install command.** The selected Bun runs `install --frozen-lockfile --production --ignore-scripts` in the
   `engine/` folder of a checkout, after a check that `engine/bun.lock` exists. No lifecycle script runs. The command
   runs in four places: `installEngine` of `engine/lib/install/installation.ts` (`celetis install` and
   `celetis update`) in the staging folder; `scripts/worktree-setup.ts`, the worktree setup of a lane
   (`worktreeSetup` in `.celetis.yaml`); CI, before the tool install; and the hand command of "First install". A
   version folder is complete with its packages, or absent. A revision with no `engine/bun.lock` refuses with exit 3,
   and a failed install refuses with exit 6; each removes the staging folder and leaves the engine unchanged.
3. **The gate checks and installs nothing.** It refuses a missing or stale install, and a `package.json` with a
   version that is not exact, with a line that names the install command. It needs no network.
4. **`engine/lib/vendor/` is gone.** `yaml.mjs`, `yaml.d.mts`, the license, the README, the SHA-256 check, and each
   vendor role of the gate go. Each engine import of `yaml` names the package.
5. **No path across the change.** An engine installed before this change runs its own old updater, which moves the
   engine to a version folder with no packages. Each machine runs "First install" once in place of `celetis update`.
   A machine that already ran the old update runs the install command in its current version folder, which the
   README gives. This follows ADR-0091 and ADR-0114: no compatibility path and no guard.
6. **The daemon protocol is the first parser area of epic #341.** The parsers of `engine/lib/daemon/types.ts`, the
   parsers of `engine/lib/queue/queue.ts`, and `sessionEnv` of `engine/daemon.ts` check their input with Zod schemas,
   and their types are the types of those schemas. Each keeps its refusal line and exit code. The one change: the
   session environment file now refuses a `__proto__` key, which `z.record` would drop in silence.
7. **The packages are for the engine only.** Later children of the epic add schemas on this layer.

## Constitution

Read: `CONSTITUTION.md`, amended 2026-11-12.

- Serves: 1 Intent to release: the daemon protocol, which starts and lands each change, gets one checked definition
  per value, for fewer parser bugs.
- Serves: 3 Verified landing: the gate refuses a stale or missing install, so a suite result belongs to the packages
  of the tip that lands.
- Tension: 2 Autonomous steps: an install or an update needs the npm registry when the Bun cache does not hold the
  locked packages, and the update across this change needs one manual first install on each machine. Goal 1, and
  the choice of the established way, win.
- Hard limits and non-goals: none touched. No agent approves an update; the maintainer runs the first install.

## Alternatives considered

- **One manifest at the repository root.** One lockfile could serve the engine and the gate tools, but it puts
  package files at the root for packages that only the engine uses. The maintainer rejected it.
- **A copy of each package, or a committed bundle.** The maintainer rejected it (parent decision 3).
- **`bun install --frozen-lockfile --dry-run` in the gate.** It resolves and downloads before it refuses (the plan
  probe), so the gate would need the network.
- **A split import graph, so that the entry runs with no package.** It is a second rule for each later child. The
  entry and the install path keep their static imports.
- **A guard or a repair for an engine installed before this change.** The maintainer's rule forbids a compatibility
  path, and the cost is one first install for each machine.
- **A discriminated union for the queue record.** It changes the type that each caller narrows, and no defect of the
  cross-field rules is known. They stay as refinements.

## Consequences

- One Zod schema is the check and the type of each value of the daemon protocol, and the private shape helpers of
  `engine/lib/daemon/types.ts` and `engine/lib/queue/queue.ts` are gone.
- Each install and update needs the npm registry, or the registry of the Bun configuration, only when the Bun cache
  does not hold the locked packages. An offline update with a cold cache stops with exit 6.
- Each machine needs one first install to cross this change, and each lane worktree and CI run the install first.
- A process that loads the schemas pays the import of Zod, about 11 to 13 ms in the probe of the spec.
- A version folder that already exists gets no new install: `installEngine` finds the complete clone and
  `holds` accepts it. The repair of such a folder is the install command by hand.
- `engine/node_modules` is ignored by Git, and a pull that changes `engine/bun.lock` needs the install command again.

## Reconsider when

- Zod or `yaml` needs a lifecycle script, or Bun changes the meaning of `--frozen-lockfile` or `--ignore-scripts`.
- The engine needs to update with no registry access and a cold Bun cache.
- The gate tools of `scripts/` move into a manifest (#353), and the question of one lockfile comes back.
- The start cost of Zod is too high for the commands that load the schemas.
